Modernizing a decade-old tax codebase

Case study · Kominvent s.r.o. · May – July 2026 · ← nrcode.com

Context

Kominvent s.r.o. is an accounting office in Komárno, Slovakia — my client since 2013. Their business runs on custom software I built and still maintain: tax-return calculation producing filled PDF and XML forms, invoicing, and internal admin tools.

The codebase is Yii2-based PHP that has grown for over a decade. Slovak tax law changes every year, so every year the software has to change with it.

Challenge

After ten-plus years of yearly deadline-driven updates, the code showed its age:

  • financial math done with raw bc* calls scattered across the codebase
  • business rules tangled into controllers and framework models
  • little static analysis, thin test coverage around the critical calculations
  • a PHP runtime falling behind supported versions

Each yearly tax-law update meant touching fragile code where a rounding mistake ends up on someone's tax return.

Approach

Tests first, then refactor — never the other way around:

  • wrote characterization ("golden") tests to pin down the current behaviour of every calculation before touching it
  • extracted a domain layer — value objects, calculators, services — out of controllers and models, so business rules live in plain, tested PHP classes
  • migrated all financial math from raw bc* calls to PHP's BcMath\Number behind a small null-aware helper
  • raised PHPStan from level 5 to level 8 across the codebase
  • upgraded the runtime to PHP 8.4, deleted dead code and modernized the development environment

Results

  • a type-safe codebase passing PHPStan at level 8
  • business rules in a tested domain layer, decoupled from the framework
  • all financial math on BcMath\Number — precise, consistent rounding everywhere
  • a modern PHP 8.4 runtime
  • 400+ commits over two months, with the software in production the whole time

What this buys the client: the yearly tax-law updates are now faster and safer to ship.
